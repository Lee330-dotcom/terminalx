## Context

终端数据通路目前是纯透传：主进程 `SessionManager` 维护 xterm 字节流与滚动缓冲，渲染进程只做显示与输入转发。已有一套本地 MCP 服务把 SSH 能力开放给外部 AI 客户端，但应用自身没有模型接入。参见 proposal.md 了解动机。

## Goals / Non-Goals

**Goals**

- 用最小改动接入 OpenAI 兼容的 Chat Completions 流式接口
- 三个分析场景共用一条请求/流式通道与一个结果面板
- API Key 复用现有加密凭据库，不新增密钥管理机制

**Non-Goals**

- 不做多轮对话、上下文记忆
- 不做 Markdown 富文本渲染（按纯文本 + 保留换行展示）
- 不做命令生成/执行（属于后续半自动、全自动阶段）
- 不引入新的 npm 依赖

## Decisions

### 1. 模型接入：可配置 OpenAI 兼容端点，而非绑定某一家

设置里存 `aiBaseUrl` 与 `aiModel`，调用 `POST {baseUrl}/chat/completions`。这样内网中转、公司网关、DeepSeek/通义等兼容端点都能直接用，也避免为每家写适配器。备选是只支持 Ollama，但用户明确选择 OpenAI 兼容网关。

### 2. 密钥存储：复用 CredentialVault

`SecretPayload` 增加可选 `apiKey` 字段，AI Key 以固定 id 存在加密凭据库；`Settings` 只保存 Base URL 与模型名。备选是把 Key 放 settings.json，但那是明文，直接排除。

### 3. 请求形态：主进程发起、渲染进程订阅流式事件

渲染进程调用 `ai:analyze(kind, ...)` 得到 `requestId`，主进程用 Node 内置 fetch 读取 SSE，按 `ev:ai:chunk` 推送增量、`ev:ai:done` 结束。备选是渲染进程直接请求模型，但会绕过主进程的密钥保护并受 CORS 限制。

### 4. 上下文来源：解释用渲染层选区，摘要用主进程滚动缓冲

选段解释的文本本来就在 xterm 选区里，直接由渲染进程传入；摘要由主进程 `sessions.readLines(sessionId, 300)` 读取，避免 300 行文本走一次 IPC 往返。诊断由渲染进程传错误信息与非敏感元数据（主机/端口/用户名/认证方式）。

### 5. 提示词：系统角色固定为只读运维助手

三个场景共用一段 system prompt：只做分析、不给可直接粘贴执行的高危命令、不声称已执行任何操作；输出结构固定为「结论 / 可能原因 / 建议排查步骤」。构造器为纯函数，便于单测。

### 6. 交互：右侧抽屉 + 三个入口

- 终端选段后鼠标位置附近浮现「AI 解释」按钮（监听选区变化，取消选中即隐藏）
- 标签栏放「AI 摘要」按钮，仅在当前标签已连接时可用
- 错误态页面在「重新连接」旁放「AI 诊断」
- 抽屉固定在右侧，宽 380px，可在请求中停止、结果可复制

### 7. 错误与边界

- 未配置：不请求模型，抽屉展示配置引导
- HTTP 非 2xx：展示状态码与响应体前 500 字
- 网络/超时：120 秒上限，展示可读错误
- 新请求自动中止旧请求，只保留最新结果

## Risks / Trade-offs

- [日志可能含敏感信息] → 摘要固定只取最近 300 行，抽屉标注发送范围；入口均由用户主动触发
- [兼容端点行为差异（流式格式、模型名）] → 设置页提供「测试连接」，错误信息原样展示
- [长输出导致面板卡顿] → 纯文本渲染 + 上限提示；流式增量按帧追加
- [模型给出危险命令] → 本阶段完全无执行通路，输出仅作文本展示

## Migration Plan

无数据迁移：新设置字段有默认值，凭据库新增字段向后兼容。升级后功能处于未配置状态，填好配置即启用。
