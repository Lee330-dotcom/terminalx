## Why

只读分析解决了「看懂输出」，半自动解决了「命令怎么写」，但排查仍是人一步步点。全自动阶段要让助手在一次任务里自己读信息、判断下一步：只读查询自动执行并回填结果，变更类命令停下来等用户确认，在效率和可控之间取平衡。

## What Changes

- AI 抽屉新增「分析 / 助手」页签；助手页为多轮对话时间线，绑定当前已连接标签页
- 主进程新增 Agent 循环：通过 OpenAI tools/function calling 调用 `execute_command`，把结果回填给模型继续推理
- 执行走现有 MCP `exec_command` 的独立 exec 通道，不写入用户终端；单条 60 秒超时、50KB 截断
- 本地命令策略在主进程强制执行：只读白名单内自动执行，白名单外、含重定向/命令替换/`sudo`、敏感路径的命令必须用户确认
- 单次任务最多 8 次工具调用，超过后强制模型总结；多行命令禁止执行
- 设置 → AI 新增「允许自动执行只读命令」开关，默认关闭；关闭时所有命令都需要确认
- 对话时间线展示用户消息、AI 文本、工具卡片（命令/风险/状态/可展开输出）、待确认卡片（执行/跳过）与错误/停止状态

## Capabilities

### New Capabilities

- `ai-agent-assistant`: 对话式运维助手，包含受控命令执行、只读白名单、审批流、步数与超时限制、会话隔离和设置开关

### Modified Capabilities

（无：只读分析与半自动命令建议的行为契约不变）

## Impact

- 共享类型：新增对话请求、审批、取消与流式事件类型；设置项 `aiAutoExecute`
- 主进程：新增命令策略模块与 Agent 服务；复用 AI 配置、`ctx.ssh.exec`、输出截断与凭据库
- IPC/preload：新增启动对话、批准/拒绝、取消与事件订阅
- 渲染进程：AI 抽屉页签、助手时间线、审批卡片、输入与停止；切换/关闭标签清理对话
- 设置页：AI 分区新增自动执行开关与说明
- 测试：策略单测、Agent 流程单测、e2e（本地 SSH + mock tools 模型）、真实端点验证
