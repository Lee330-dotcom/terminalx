## Context

只读分析已提供 `AiService`（OpenAI 兼容流式调用）、右侧 `AiPanel` 抽屉与会话滚动缓冲读取能力。终端输入通路是渲染进程 → `sendInput` → SSH 流的纯透传，没有「半自动」路径。参见 proposal.md 了解动机。

## Goals / Non-Goals

**Goals**

- 在现有 AI 链路上增加「自然语言 → 命令建议」，复用流式、取消、配置与密钥保护
- 命令建议必须经过用户操作才进入终端，且默认只插入不回车
- 用本地规则 + 模型标注给出风险等级，避免盲目执行
- 解析与风险规则做成纯函数，可单测、可独立演进

**Non-Goals**

- 不自动按回车、不自动执行、不调用 MCP 工具
- 不做多轮对话、命令历史学习、定时日志巡检
- 不做 Markdown 富文本渲染（命令卡片为结构化补充，正文仍为纯文本）
- 不引入新的 npm 依赖

## Decisions

### 1. 复用 `command-suggestion` 分析类型，而非新建对话接口

在 `AiAnalysisKind` 中增加 `command-suggestion`，请求带 `instruction` 与 `sessionId`。主进程读取该会话最近 120 行作为上下文（与摘要的 300 行独立的常量），一次请求一次结果，沿用现有 `ai:analyze`/`ai:cancel`/流式事件，不新建通道。

备选是引入多轮聊天接口，但本阶段只需要单轮生成，多轮留给全自动阶段。

### 2. 输出格式用 Markdown 代码块，解析失败退化为纯文本

系统提示词要求固定结构：

```
### 1. <一句话说明>
风险：低|中|高
```bash
<单行命令>
```
```

结束后由渲染进程解析第一个 `bash`/`sh`/`shell` 代码块及其邻近的说明与风险行。解析失败时不渲染卡片，仅保留正文与复制按钮——不阻断使用，也不猜测命令。备选是让模型输出 JSON，但流式过程中可读性差，且兼容端点对 JSON 模式支持不一。

### 3. 落地方式：只插入、不回车（用户确认）

卡片「插入终端」调用 `sendInput(sessionId, command)`，只写入命令文本，不追加 `\r`。用户自己按 Enter 执行。多行命令（含换行）禁止插入——内部换行会被 shell 立即执行，违背「不回车」的安全边界；仅保留复制。

备选是「插入 + 二次确认执行」，但用户明确选择只插入模式，风险最低。

### 4. 风险分级：本地规则与模型标注取较高者

本地规则覆盖删除、磁盘写入、重启、权限、数据库破坏性语句等明显高危模式；模型可在结构里标注低/中/高。两者合并：命中本地高危即高，否则取模型标注；没有标注时按「未知」展示。风险只做提示，不阻断（因为不回车）。

### 5. 插入目标锁定发起时的会话

请求发出时记录 `sessionId`；卡片按钮在会话已关闭或断开时禁用并提示重连。避免把 A 会话的命令插到 B 会话。

### 6. 交互位置：AI 抽屉底部输入框

仅当当前标签处于已连接状态时启用输入框，占位文案说明可做的事。生成期间可停止；新指令自动中止上一条请求。卡片固定展示在正文上方，插入后标记「已插入」，避免重复写入。

## Risks / Trade-offs

- [模型输出格式漂移导致解析失败] → 解析失败退化为纯文本，复制仍可用；提示词给出严格模板与示例
- [上下文含敏感日志] → 固定只发最近 120 行，面板标注发送范围；由用户主动发起
- [用户误按 Enter 执行高危命令] → 本地风险规则高亮 + 文案提醒；插入不回车，保留人工确认环节
- [命令内换行被直接执行] → 多行命令禁止插入，只能复制
- [会话在生成期间断开] → 插入按钮按会话状态禁用，提示重新连接
